## Dependency conclusions

- Calibration is protected by equality to USER_REQUESTED: `src/crypto_probability_engine/calibration/service.py:55`, `src/crypto_probability_engine/persistence/repository.py:3158`, `:3816`. Expanding the enum alone does not add radar rows to ordinary calibration or the skill refresh. Shadow validation retains the same origin default. The cache is keyed only by timeframe; its upstream selection is the boundary.
- `/v1/runs` and human detail enforce USER_REQUESTED (`src/crypto_probability_engine/api/app.py:314`, `:330`). The lower-level run store and `/v1/debug/runs` do not. REST recent runs fetch a bounded unfiltered candidate window before filtering (`repository.py:2164`); additional nonhuman summaries could crowd out human results even though those summaries are not returned.
- Generic due readers default to `prediction_origins=None`; the current resolver explicitly supplies USER_REQUESTED on both paths (`scripts/resolve_outcomes.py:227`, `:236`). These lower-level defaults remain open even when current callers are safe.
- OOS selection deliberately uses namespace/arm/methodology rather than origin (`repository.py:3709`). Unexpected origins are counted, not silently filtered. A radar-origin row with a matching OOS identity changes control/anomaly diagnostics and is read before downstream gates; an ordinary radar run ID cannot enter this population.
- Target v1 rejects SCHEDULED_SHADOW_EVIDENCE rather than positively allowing human origins (`targets/contract_v1.py:284`); an otherwise valid radar row would pass that origin check.
- F1 currently writes none of these stores. Its separate automation ledger is not selected by any cohort reader. The hypothetical future-origin hazard is not a finding of current cohort contamination.

Verdict: YES—adding AUTOMATED_RADAR to shared prediction-origin semantics could admit it through unfiltered generic/control readers by default (OOS requires matching namespace), while current calibration, skill refresh, shadow validation and the production resolver retain explicit USER_REQUESTED filtering.
